### What happens?

As indicated in upstream reference: duckdb/duckdb/discussions/22301, when `read_parquet` is used on multiple files it uses the first read files to guess the schema, including which columns are there if `union_by_name=false`.

When reading another file the schema is incompatible, the error message is quite concise:

```_duckdb.ConversionException: Conversion Error: Unimplemented type for cast (VARCHAR -> "NULL")```

this message does not report *which* column could not be cast, nor on which file, making it quite hard to troubleshoot. I only know that some column in some file was missing; the same thing happens if the column type is different across different files.

### To Reproduce

Example code (sadly the data on which I found this is private, but I think the issue is quite clear even without reproducing it).

```
SELECT DISTINCT x
FROM read_parquet('s3://my-bucket/data/**/*.parquet')
WHERE y = 123
```
